# V5 Accessibility Walk-Through

**Scope:** Read-only V5 baseline walk-through across the web client surfaces in Chrome and Firefox against the isolated fixture server (`startFixtureServer()` in `scripts/lib/ui-fixture.js`).

> Automated checks and screenshots establish observable baselines and concrete failures, and do not replace owner acceptance or manual assistive-technology sign-off.

**Five checks run per surface:**
1. **Keyboard only:** `Tab` / arrow / `Home` / `End` / `Enter` / `Space` / `Escape` navigation, visible focus ring styles (`getComputedStyle`), initial dialog focus, focus containment, and focus return.
2. **200% and 400% zoom:** Layout reflow at `640×450` (equivalent 200% at `1280px` width) and `320×500` (equivalent 400% at `1280px` width), plus `390×844` phone width; `scrollWidth <= clientWidth` checks; inspection of inline geometry written by `web/watch-sidebar.js` and `web/watch-toasts.js`.
3. **Forced colours:** Legibility, boundaries, focus rings, icon/brand visibility, and selected/pressed states under Chrome CDP forced-colours emulation and Firefox High Contrast profile preferences.
4. **Structure:** `h1` count and heading order (`h1`–`h6`), landmark roles and labels (`header`, `nav`, `main`, `aside`, labelled `section`), accessible names, `role="status"` / `role="alert"` / `aria-live` regions, and non-colour cues.
5. **Targets:** Interactive control bounding boxes (`>= 40×40 px`), accounting for the approved exceptions in [`docs/design-guide.md`](design-guide.md) (queue timeline move/remove buttons `32×32 px`, and `24×24 px` `.room-roster-sync-quality`).

**Methodological note on multi-tab Firefox BiDi runs and surfaces outside the default demo fixture:**
- During initial multi-tab walkthrough sweeps, issuing `browsingContext.activate` before each Firefox `Tab` keystroke caused top-layer scrollable containers (`OverlayScrollbars` on `dialog.watch-dialog` and `#room-participants`) to refocus the container instead of stepping sequentially. Follow-up verification in `playbackBrowser('firefox')` without per-keystroke activation confirmed authentic Firefox `Tab` order for `#account-dialog`, `#room-share-dialog`, `.transport`, and `#volume-panel`, as well as real Firefox focus issues on `#room-share-url-input`, `#queue-bulk-dialog`, `#codec-test-dialog`, and modal `<dialog>` boundary wrapping.
- Three UI flows were not opened live in the default `?demo=host` fixture and were verified by source inspection: `#entry-form` / `#guest-join` / `#invite-code-form` (password/guest sign-in inside `web/watch.html`), `#handoff-dialog` (Discord Activity-only browser approval, `web/watch.html:1369-1378`), and `#server-settings-dialog` (requires local server owner session without `store.identity.token`, `web/watch/account.js:50-54`, `web/server-settings.js`).

## Cross-Cutting Findings

### 1. Inconsistent Focus Indicators (Violates "One focus ring everywhere")
[`docs/design-guide.md`](design-guide.md) requires one focus ring everywhere. Measured keyboard focus styles currently diverge across five rules:
- **White `3px solid` (`var(--text)`), `outline-offset: 3px`:** Base rule on `button, a, input, select` in [`web/styles/controls.css:59-65`](../web/styles/controls.css#L59-L65).
- **Orange `2px solid` (`var(--primary)`), `outline-offset: 2px`:** `.watch-control`, `.watch-focus`, `.watch-segmented button`, `.watch-switch`, `.watch-panel-heading button`, and `.watch-switch-pill:has(:focus-visible)` in [`web/styles/controls.css:554-561,625-628`](../web/styles/controls.css#L554-L561), plus `.room-roster-sync-quality` in [`web/styles/rooms.css:371-374`](../web/styles/rooms.css#L371-L374).
- **Pink (`var(--secondary)`):** `3px solid` on `#queue-auto-toggle` / `#queue-auto-specials` in Chrome (via `outline-color: var(--secondary)` in [`web/styles/queue.css:686-688`](../web/styles/queue.css#L686-L688)), and `2px solid` on `.queue-auto-mode-group .group-button:focus-visible` ([`web/styles/controls.css:786-788`](../web/styles/controls.css#L786-L788)).
- **Missing `textarea`, `summary`, `[tabindex]` from `controls.css:59-65`:** `#event-description` (`textarea` in `#event-dialog`) and `<summary>` (`Technical details` in `#tracks-dialog`, admin panel in `#account-dialog`) drop to a `1px` default outline (`rgb(238, 238, 238)` in Chrome, `rgb(248, 247, 244)` in Firefox).
- **Suppressed outlines:**
  - `#room-share-url-input { outline: none; }` in [`web/styles/share.css:32-35`](../web/styles/share.css#L32-L35) yields `outlineStyle: none` in Firefox during keyboard focus (relying only on parent `.room-share-link-dock:focus-within` border colour change).
  - `.watch-toast { border: 0; outline: 0; }` in [`web/styles/toasts.css:28-29`](../web/styles/toasts.css#L28-L29) relies on `button:focus-visible` specificity winning for actionless `<button class="watch-toast">`, while `.watch-toast-action` / `.watch-toast-dismiss` set a separate `2px solid var(--text); outline-offset: 2px` in [`web/styles/toasts.css:135-139`](../web/styles/toasts.css#L135-L139).

### 2. Forced Colours Regressions (`@media (forced-colors: active)`)
No forced-colours stylesheet rules exist in `web/styles/` apart from `vendor.css:18` and `watch-scrollbars.js:31` disabling custom scrollbars. Under both Chrome CDP `forced-colors: active` and Firefox High Contrast preferences:
- **Zero-border controls lose boundaries:** Measured `border: 0px none` on `.appearance-track`, `.appearance-thumb`, `#admin-mode`, `.watch-switch-pill`, `input.watch-switch`, `.primary`, `.quiet`, `.watch-toast`, `.watch-toast-action`, `#room-settings-nav button`, and `.button-group button` (both browsers).
- **Selected/active states collapse in Chrome:** Both `#room-settings-nav [aria-current="true"]` and `.button-group [aria-pressed="true"]` render with `bg: rgb(0, 0, 0)`, `color: rgb(255, 255, 255)`, `border: 0px none` — visually indistinguishable from unselected items in [`chrome-fc-room-settings.png`](../uburoom-evidence/artifacts/v5-accessibility/chrome-fc-room-settings.png).
- **Custom switch tracks & knobs vanish:** `.appearance-track`, `.appearance-thumb`, `#queue-autoplay`, and `.watch-switch` lose background fills without borders/tracks (`chrome-fc-room.png`, `firefox-fc-room.png`).
- **Wordmark SVG invisibility in Firefox High Contrast:** `<img class="brand" src="/assets/branding/uburoom-wordmark-brand.svg">` (`web/watch.html:49`) has hardcoded white lettering for `room`, which disappears completely against Firefox's `#FFFFFF` High Contrast canvas ([`firefox-fc-room.png`](../uburoom-evidence/artifacts/v5-accessibility/firefox-fc-room.png), [`firefox-fc-lobby.png`](../uburoom-evidence/artifacts/v5-accessibility/firefox-fc-lobby.png)).

### 3. Structure: Headings, Landmarks, and Skip Link
- **No skip link and top header inside `<main>`:** [`web/watch.html:46-47`](../web/watch.html#L46-L47) places `<header class="account" id="account">` inside `<main>`. There is no top-level `<header>` banner outside `<main>` and no skip-to-content / skip-to-player link.
- **Unlabelled `<header>` and `<section>` landmarks:** Four visible `<header>` elements lack `aria-label` or `aria-labelledby`: `#account` (`watch.html:47`), `#library-header` (`watch.html:971`), Room `.watch-panel-header` (`watch.html:1106`), and `.queue-header` (`watch.html:1268`). Modal `<dialog> > header` elements add another 11 unlabelled `<header>` nodes in DOM queries when closed. `<section id="library-panel">` (`watch.html:970`) and `<section id="options-panel">` (`watch.html:1105`) also lack accessible names (`#viewing-section` and `#queue-panel` are properly named).
- **Heading level skips and missing `<h1>`:**
  - Lobby skips `h1 -> h3`: `#empty-title` (`<h1>`) -> `#lobby-events-title` (`<h3>Upcoming</h3>`, `watch.html:186,313`).
  - Room skips `h2 -> h4`: Room title `<h2>` (`watch.html:1107`) -> `<h4 class="room-roster-heading">Viewers</h4>` (`watch.html:1165`).
  - Room Settings Playback skips `h2 -> h4` (`Auto-queue`).
  - Room Settings at `<= 620px` hides `.room-settings-panels > section > h3 { display: none; }` (`web/styles/rooms.css:252-254`), causing visible `h2 -> h4` skips (`Transfer room leadership`, `Saved room`).
  - Ending interstitial (`#ending-stage`): `web/styles/exceptions.css:54-58` hides `.player-chrome.title-bar` (containing `<h1 id="title">`), leaving `visibleH1Count = 0` (`<h2>#ending-title</h2>` becomes the highest heading).

### 4. Inline Positioning Geometry Leftovers (V3 Rule)
[`docs/design-guide.md`](design-guide.md) states positioned menus and popovers receive coordinates as custom properties (`--x`/`--y`) and script never writes other geometry. Two modules still write direct pixel geometry inline:
- [`web/watch-sidebar.js:38`](../web/watch-sidebar.js#L38): sets `column.style.top = "${stickyTop}px"` on `#room-column` at `(min-width: 1101px)` (observed `top: 22px;` in Lobby, `top: -328px;` at `1280×900` Room, `top: -478px;` at `1280×480` short desktop viewport). Clears `top` at `<= 1100px` (`phone` layout at 200%/400% zoom).
- [`web/watch-toasts.js:34,49-50`](../web/watch-toasts.js#L34): writes `host.style.maxWidth`, `host.style.top`, and `host.style.left` on `#watch-toasts` (e.g., `max-width: 773.328px; top: 55.9531px; left: 40px;` at `1280×900`, `max-width: 300px; top: 0px; left: 10px;` at `320×500`, and retains stale `max-width: 620px; top: 30px; left: 10px;` immediately across resize from desktop to `320×500` when toast position is not yet re-run).
