# Upgrading

uburoom uses `/ubu` and `!ubu` exclusively. At startup, the bot replaces this application's command set in its configured guild with `/ubu`; it does not change commands belonging to other applications or publish global commands.

The Firefox extension ID is `uburoom@uburoom.com`. Install it as a new extension and pair it with your installation. Its private authentication callback is derived from that ID. Configure the build for your installation's exact HTTPS origin. There are no previous-name aliases for extension identity, storage, cookies, globals, protocol fields, launchers or logo routes. Browser users must sign in again after the naming transition.

Keep existing account UUIDs, linked identities and encrypted data. Before starting an existing database, copy the exact original 32-byte encryption key into the runtime user's `LOCALAPPDATA/uburoom/credentials.key` (or the equivalent home directory on other platforms), or set `UBUROOM_CREDENTIAL_KEY_FILE` to its private absolute path outside the project. Never generate a replacement key for existing accounts. Back up the matched database/state and key before upgrading; startup refuses an existing database with a missing key.

Use only the uburoom launchers. Select a tested revision, install dependencies on the runtime machine and restart during an agreed maintenance window. Keep private state outside Git and preserve it when replacing code. See self-hosting.md for backups/deployment and testing.md for pending live verification.

M1-P11 adds schema version 1 and imports `data/devices.json` and `data/logins.json` into `accounts.sqlite` on the first upgrade. Import markers prevent old files from restoring revoked devices or logged-out browsers. Account UUIDs and the original external key remain unchanged; OAuth refresh credentials are encrypted in the database. The legacy files are retained as pre-upgrade rollback inputs and are no longer updated. After validating a matched offline backup and the upgrade, archive those files privately; they may contain old credentials. Never copy them over current SQLite state.

Runtime writes are serialized by a worker into this one database. HTTP completions and WebSocket request acknowledgements await committed writes; shutdown flushes outstanding work. An abrupt process loss can discard observations not yet acknowledged. A storage failure is reported and prevents successful durability acknowledgements. Stop the server before an ordinary file-copy backup, or use SQLite's online backup; copying the file during a transaction is unsafe. Rolling back to code that reads JSON needs a deliberate matched pre-upgrade restore and loses changes made since that backup, including sign-outs and revocations.

Reload open watch pages after upgrading to watch protocol 16. Allow WebSocket upgrades for `/watch-socket` through the installation's HTTPS proxy, as well as `/ws` for the Firefox remote. Authentication/account bootstrap and media remain HTTP. There is no HTTP room-polling fallback. A socket disconnect revokes consent and ends that viewer's stream; a same-tab rejoin within the process-local grace obtains fresh playback authority and retains personal track choices. A daemon restart clears rooms and consent.
