# Approved screen behavior

This reference holds owner-approved, feature-specific UI decisions moved from the [design guide](design-guide.md). Consult only the relevant section for the surface being changed. These decisions are not permission to redesign unrelated surfaces; common controls, tokens, focus, layout and feedback principles remain in the design guide.

## First-run setup

The owner accepted the implemented wizard on 2026-11-21. See [first-run setup](first-run-setup.md#implementation-notes-2026-11-21). Each card shows the wordmark, the current step and Back and Next controls where applicable.

- **1 Setup code:** one large field, filled in and submitted automatically from the link's `#code=`; otherwise typed. A wrong code says so; the tenth says a new code is shown.
- **2 Your account:** Sign in with Plex (pop-up; the card waits with Open Plex again and Cancel) or Create a uburoom account (Username, Password, "At least 10 characters."). Done shows the name, "Signed in with Plex" or "uburoom account", and Change.
- **3 Media sources:** the list (logo or folder icon, name, "Plex · 3 of 4 libraries" or the folder's path, Edit and a Remove icon), "Add at least one to continue." when empty, and Add Plex / Add Jellyfin / Add a folder. Each add flow and Edit replaces the list in the card, as in Server settings → Sources: Plex uses the step 2 Plex sign-in when there is one; Jellyfin shows found servers, then the administrator sign-in (with the Quick Connect code when the server has it), then "Offer the libraries of" and the libraries; a folder shows the folder browser, Name and Contains Movies/Shows. Edit: Name, where it is, and the library checkboxes (a folder: Contains). Remove needs no confirmation (nothing is saved yet).
- **4 Who can get in:** one checkbox and hint per rule. Discord shows the redirect, application credentials, bot invitation, and joined servers. Each server starts checked and can be excluded by unchecking it. For counts above 500, show how many members may gain access. Preserve draft exclusions across list refreshes. The rule the operator's own account uses is on and disabled with "Your account gets in this way."

- **5 Where will people watch?:** This computer / My home network, Port, the address people open (home network: the certificate warning line), and the remote access guide line.
- **6 Check and finish:** one row per check with a check mark or cross and its detail; Check again when any fails; Finish setup (Finishing… while it writes and starts uburoom). With Discord enabled, show the final OAuth2 redirect and the instruction to replace an earlier address in the Developer Portal.
- **Ready:** "uburoom is ready", "You're signed in…", Open uburoom.

Server settings → Rooms exposes room limits and the full host/viewer permission matrix from `CAPABILITIES` (including **Suggest media** (`suggestMedia`) for host and viewer roles, keeping management permissions viewer-blocked). Server settings → Access exposes the entry rules for operators: media server members (`access.source_members` checkboxes for each configured Plex and Jellyfin source), the local uburoom accounts master switch (`access.accounts`), server password (`access.password` with a write-only 8+ character password field), Discord server entry (`access.discord_server`) with the Discord server exclusion list and >500 member warning nested beneath it, and room guest invites (`guests.enabled`). It blocks saving with zero entry rules enabled and warns when the selected rules no longer cover the current operator's own sign-in method. Server settings → Accounts shows a banner when `access.accounts` is off in running or saved settings (with a shortcut to Access). Adding a Plex or Jellyfin source in Server settings → Sources offers a checkbox to also allow its members to sign in (`access.source_members`). Save writes to YAML and applies after restart.

## Media sources

The owner accepted the Sources panel on 2026-11-21. Its media-source flows follow the setup wizard and use the Accounts section's styles.

- **Server settings → Sources:** a tab between Transcoding and Accounts. Changes save immediately to `config.yaml` and apply after restarting uburoom. The panel can load independently of the saved settings form. On narrow screens the tabs wrap.
- **List:** one row per saved source in config order: Plex or Jellyfin logo or a folder icon, the name (or id), "Plex · 3 of 4 libraries" (a folder shows its path), a warning line when its check fails, and "Saved · applies after restart" when it differs from what is running. Edit and a Remove icon button on the right. Sources removed but still running are named in one line below. Then Add Plex, Add Jellyfin and Add a folder.
- **Edit:** inline in the panel: Name (placeholder the id), the address, and "Libraries to offer" checkboxes with item counts and "Libraries added to this server later start off." Cancel and Save source.
- **Edit a folders source:** Name, then one bordered box per library: its Name, a Movies/Shows segmented selector and a Remove library icon button (disabled, with the reason as tooltip, when it is the only library), its folders one per row with a remove icon button (disabled when it is the library's only folder), and Add a folder. Below the boxes, Add a library and a hint that videos keep their history when a library is renamed or changes type. Add a folder and Add a library open the folder browser in the panel ("Add a folder to Films", or "Add a library: choose its first folder") with Back and Use this folder; a new library is named after its folder and starts as Movies. Nothing is saved until Save source.
- **Remove:** an inline bordered confirmation: "Remove Name?", that its libraries are no longer offered after a restart and that queue history and resume positions are kept and come back if the server (or folder, with the same name) is added again. Cancel and a danger Remove.
- **Operator sign-in at risk:** the confirmation for a Jellyfin sign-in source warns when removing it could cut off a configured operator. Verify another sign-in opens Server settings before removing the source. After saving, the panel identifies the private recovery backup.
- **Add Plex:** Sign in with Plex opens plex.tv in a pop-up window and the panel waits ("Open it again" if the window was blocked or closed). Then "Signed in as name. Choose a server." with a radio per server and its address; unreachable servers are disabled with "uburoom can’t reach this server from this computer". "Enter an address instead" with Test. Choosing a server shows Name (placeholder the server's name), the address and the libraries, all on, then Add server.
- **Add Jellyfin:** servers found on the network as radios, "Enter an address instead", Next; then "Sign in to Server" with Username and Password and, when the server has it, Use Quick Connect instead (shows the code large, and waits for approval); then "Offer the libraries of" a user dropdown, Name and the libraries, then Add server.
- **Add a folder:** the current path, a bordered list of folders (Up one level first; drives at the top on Windows), Name (placeholder the folder's name), Contains Movies or Shows, Add folder.
- **While waiting** for a sign-in, every control but Cancel is disabled; Cancel ends the wait. Each step's error shows on the panel's error line.

## uburoom accounts

- **Server settings → Accounts:** a fourth tab after Transcoding. Unlike the other tabs it saves nothing for a restart: each action applies at once, and it works even when saved settings can't load. A hint says so. Username and Display name (optional, "Same as username") with Add account, then one row per account: name, username and status (Active, Waiting for password with the link's expiry, Disabled), with New link and Disable, or Enable when disabled.
- **The link:** shown once, in a bordered box under the form, after Add account or New link: "Send this link to Name. It works once, until <time>. It won't be shown again.", a selected read-only field and Copy link. Closing the dialog forgets it.
- **Set-password page** (`/account/password`): the hand-off page card: "Set your password" (or "Choose a new password" for a recovery link), "For Name (username).", New password, Confirm password, "At least 10 characters.", Set password, then it opens uburoom signed in. A used or expired link shows only its message and Back to uburoom.
- **Sign-in form** (`web/account-sign-in.js`): Username, Password and Sign in in the entry form style, with one error line ("Wrong username or password", or the rate-limit message). It is a component for the entry page, which decides when to show it.

## Watch nights

A watch night is a room with a time on it: every event belongs to one saved room, and choosing media stays in the room's queue, never in the scheduler.

- **Entry points:** the lobby room bar shows Schedule between Reopen room and New room; inside a room, a calendar button beside Share opens the same scheduler for that room. Only people who can schedule there see them (the server's scheduler tier, and hosting for the room button); nobody else sees a disabled one, and guests never do.
- **Scheduler:** one workspace dialog for both entry points and for editing. Its first row is Room, defaulting to New room (named after the event) and listing rooms the person hosts; single-room mode has no Room row. Then title (with counter), start time chips (next half-hour, tonight, tomorrow), date and 15-minute time dropdowns with a collapsible time zone, duration pills with a calculated end time, and Post to Discord (on by default when Discord is configured, hidden otherwise). Footer: Cancel and Schedule (Save when editing).
- **Scheduler feedback:** submitting shows a loading popover, then any error popover, on the Schedule button. On success the dialog closes and the success popover anchors to the control that opened it. The inline status line is only for persistent messages no click caused, such as a failed load.
- **Lobby Upcoming:** above the room list, the next three events the person can see (an event follows its room's visibility), with More for the rest, expanding in place. Rows look like the active-room rows with a calendar icon and "time · room · N interested". From start to end the card reads Starting now with Join as its main, primary action; at the end it leaves the list.
- **Card actions:** Join when the room is open; when closed, hosts get Open room and others see "Waiting for host". Hosts also get Edit, Copy invite and Cancel (with confirmation). A canceled event's confirmation anchors to the lobby Schedule button because the card leaves the list.
- **Lobby order:** the button row comes first under the intro, then the error line, Upcoming, and the active rooms, which scroll beneath when the video area is short.
- **Waiting for host:** a closed room's invite with a watch night shows the start time and "Waiting for host" until a host opens it; uburoom never opens it automatically.

## Quality and delivery

- **Original versus converted:** Original means untouched source media. When Original is selected but the output is converted, the option reads Maximum with the output codec and the badge reads `MAX`. Subtitles burned in without being chosen read "Automatic (burned in)" with a status line.
- **Automatic fallback:** keeps the viewer's selected quality in the controls and shows "Using fallback · <height>p · <Mbps> Mbps" as status with an `FB` badge. Toasts announce switching to fallback and returning. Fallback is a delivery status, not a selectable quality.
- **Stream swaps:** a quality change keeps the current stream playing, and its last frame on screen, until the new one is ready.

## Subtitles and audio

- **Sliding menu:** desktop player settings use one sliding menu: arrows open choices in place, final choices and `Tab` close it, and Back stays below the scrolling choices. The timeline shows chapter breaks with title and time on hover. Skip intro and Skip credits appear only for people who may manage playback.
- **Naming:** the rendering option is **Burn-in**; help and error text never names a provider.
- **Appearance:** text subtitles draw in their own layer, default to the outline style labelled Shadow, scale with the player (Small, Medium, Large), stay on the visible picture unless set to "On player", remain when controls hide, and lift only when controls would cover them. ASS and bitmap subtitles keep their authored placement. Settings offer colour presets, a hex input, a swatch, a background style selector (Off, Background, Shadow) and a brightness slider.
- **Audio mode:** Normal, Dialogue or Night, with hints; entirely in the browser, affecting no one else.
- **Full Player settings:** More settings opens Playback. Subtitle sync opens Subtitles at the delay control, and the Video check toast opens Media information at the check. Section navigation stays visible while its content scrolls. The phone lobby shows only Notifications.
- **Subtitle sync:** Player settings provides `−0.5 s`, a numeric input (`±30 s`, `0.1 s` step), `+0.5 s` and `Reset`, saved client-side per media item and track, with a "Subtitle sync" link from the desktop player settings menu. Keyboard adjustments (`G`, `H`, `\`) show a single coalesced toast; **Burn-in** disables the offset controls while preserving the saved non-burn offset.

## Activity sharing

- Player settings → Activity sharing shows two switches to viewers with their own sign-in on the video's media server (Plex or Jellyfin), worded for any server (owner-approved 2026-11-21): **Show what I'm watching on my media server** (on by default) and **Sync my watch progress to my account** (opt-in; resume points and watched marks). Jellyfin has no activity-only mode: it reports only while both are on.

## Picture-in-Picture

- The button sits beside Theater and Fullscreen (in Player settings on phones) and answers the `P` key.
- Where Document Picture-in-Picture exists, the whole stage moves into the floating window with its controls, skip overlays and subtitle layers, and the page shows a placeholder with Return video.
- Elsewhere it falls back to native video Picture-in-Picture; with client-drawn subtitles active, a toast suggests Burn-in to keep subtitles.

## Queue and auto-queue

- **Outside a room:** the Queue panel stays, reading "The queue lives in a room" with one line of explanation and Browse media, and no room buttons. Inside a room an empty queue reads "The queue is empty" with Browse media.
- **One layout:** a single scrolling list of history, Now Playing and Upcoming; no card view or layout selector.
- **Rows:** in the dark theme rows sit on a darkened blur of their artwork; in the light theme they use ordinary surfaces with the Now Playing tint and no artwork.
- **Scroll buttons:** "N past" and "N queued" float in strips above and below the list so neither covers a row; "N past" and its strip exist only with history, and "N queued" and its strip only while something is queued.
- **Opening a queued video in Media:** a row's title and its poster both open the video's page in Media; the title is the keyboard and screen reader route, so the poster adds no extra stop. The page loads from the video's own media server whatever library was on screen (Now Playing and Next included), stays empty until its details arrive rather than showing a title-only placeholder, and once its details arrive its library becomes the current library button (Plex and local libraries always; Jellyfin when the item's library can be found).
- **No history or nothing queued:** no placeholder text; Now Playing starts at the top, and with nothing queued nothing follows it (the empty-queue screen covers a queue with no entries at all).
- **Now Playing:** keeps the primary-accent outline rather than a transient selected state.
- **Auto-queue preview:** at most one preview row at the end of Upcoming, in the secondary accent with an `AUTO` badge and "Auto · Up in …" caption, offering Add to queue, Skip suggestion, Play now and Skip to, with no reorder arrows.
- **Auto-queue options:** four modes (Off, Continue, In order, Shuffle) and its switches use the secondary accent. In Media views the source action reads "Set as auto-queue" with the `sparkle` icon in the secondary accent.
- **Media suggestions (queue):** pending suggestions sit between Now Playing and Upcoming as one collapsed row (`bulb` icon, "N suggestions", chevron), absent when there are none and never a header badge or popup. The row is the header of a plain grey box with no outline or accent tint; expanded, the suggestions sit inside that box, each a queue-style row ranked by agreement then age, captioned "Suggested by Name +N": the top actions are the agree toggle (`bulb` with the count, filled while you agree) and Dismiss; the bottom actions are Add to queue and Play now. Buttons a person lacks permission for stay visible but disabled, as on queue rows.

## Entry

- **One list of ways in, forms on demand** (decided 2026-11-21 under the owner's delegated discretion): the entry panel starts with one same-size provider-style button per enabled rule (`access:`), in this order: Log in with Discord (`discord_server`), Log in with Plex (a member rule naming a Plex source), Log in with Jellyfin (one per Jellyfin member source), Sign in with a uburoom account (`accounts`, `user` icon), Enter the server password (`password`, `lock` icon). The invite-code row comes after the list. The account form, the server-password form and Jellyfin's password form open inline directly under their button when it is chosen; one is open at a time, and choosing another way or pressing Escape closes it (Escape returns focus to its button). The opened form's first field is focused and the form scrolled into view. When the server password or uburoom accounts is the only way in, its form opens by itself; a provider button never acts unasked. The title is "Enter uburoom" when the password is the only way in, else "Sign in to join"; the status line names the ways in that exist.
- **Every action shows a result in view:** any form, error or status line that appears (an opened form, a wrong-password error, a Quick Connect status or error) is scrolled into view within the entry panel, so pressing Sign in or Continue always shows something. Rows in the list are one grid gap apart whichever forms are open.
- **Jellyfin:** the button carries the Jellyfin logo and reads "Log in with Jellyfin", adding the source name only when more than one Jellyfin source is a member rule ("Log in with Jellyfin (Den)"). Choosing it shows "Contacting Jellyfin…", then either the Quick Connect panel (the line "Open Jellyfin → Quick Connect and enter this code", the code large and centred in the browser hand-off code style, "Expires in N minutes", and Cancel, which ends the attempt on the server and closes the panel) or, when the server has Quick Connect off, the username and password form. Errors replace the panel's content with one status line; choosing the button again retries.
- **Server password, then a name:** the password form (Continue) gives way, in the same place, to the invite guest's name form, reused: the name field with its `arrows-shuffle` reroll, pre-filled with this browser's earlier guest name or a random ubunym, the italic-guest hint, and Join. The server checks the password when the name is sent; a wrong password returns to the password form with the error, and a refused name stays to be fixed.

## Viewers

- **Telemetry cards:** sync badges in the roster are buttons opening an anchored viewer card (interactive in fullscreen; closing it leaves the drawer open). The card shows name, role, playback status, sync score and level, confidence, a plain-language explanation, freshness and per-device breakdown, and dismisses on Escape, outside click or close.
- **Health alerts:** a guest's sync icon becomes `alert-triangle` while they have an issue (warning, or danger for a player error), held briefly after it clears. Their card adds an issue line and host-only details. Issues and limits are defined once in sync core.
- **Room sync:** people who can change room settings can open it from the Viewers heading. The button shows the existing spread summary once enough samples arrive. The dialog defaults to five minutes of room spread and can show one minute, fifteen minutes, all viewer offsets, or one tab. Inspect time shows how many players reported reliable timing at that point. Freeze holds the current view while inspecting it. Missing timing appears as gaps and buffering or reconnects appear beside the affected viewer. The graph uses the current video's in-memory reports and leaves out screen and speaker delay. Other viewers cannot open it.
- **Room settings** has a stable header with the room name and active Admin mode. General shows field-level Save actions after edits and folds timestamps into Room details. Viewers leads with occupancy, sharing and the roster, followed by host search and invites. Permissions keeps the role headings visible while scrolling. Playback groups auto-queue draft actions together and separates progress reset. Room actions groups closing, leadership transfer, and permanent deletion or single-room reset with their consequences.
- Under **Room settings → Playback & queue**, the **When someone buffers** segmented selector offers **Keep playing** and **Pause for everyone**. Select the room's effective policy. The stage uses the readiness status and choices during a shared buffering pause.
- The stage can tell someone who can choose how playback continues that a blocking viewer is preparing video or lining up playback. The live status shows a reason for a single blocker. After the wait times out, the readiness card shows known reasons beside the people still waiting. A viewer without a current reason uses the generic waiting text. Stage readiness cards take precedence over toasts.
- **Roles and guests:** the host badge uses ordinary text colour for contrast in both themes; the room leader keeps the accent. Unverified guests show their name in italics with `user-question` and the label "Guest (name not verified)". Guests are never offered Make host, and the Account dialog offers them no Connect buttons.
- **Account providers:** Connect <Provider> when unlinked, Sign in to <Provider> when awaiting credentials, Reconnect when connected (including Discord, Plex, and linkable Jellyfin sources for entry or personal watch-state sync). Unlink is separate and disabled when removing it would leave no usable sign-in.
- **Human readiness check:** people who can control playback start or cancel it from a `help` icon button at the end of the Viewers heading; it never adds rows or controls to the Room panel beyond an answer icon (`check` or `clock`) beside each name. Answering happens on one stage card in the readiness-choice style ("Ready to play?", "1 of 2 ready · Waiting for Name", then "Everyone is ready"): viewers get Ready and Need a moment, people who can play get Play and Cancel. Play never starts by itself. The room's own readiness choices and recovery take precedence over the card; it auto-expires after 120 s, clears on Play and never touches decoder readiness or playback consent.

## Library and ending

- **Media header:** one row: the Media heading, Back, Forward, Home and the library buttons, with Back to top at the end only once Media has scrolled past its top (it returns to the video). Libraries that do not fit go, in order, into a "More" menu at the end of the row; the current library always stays on the row. When even it and More do not fit, one button naming the current library (truncating if it must) opens the menu with every library. Past ten libraries the menu starts with a "Find a library" box. Library buttons never shrink to icons. On phones the heading takes its own row and the navigation, libraries and Back to top share the row below it. There are no breadcrumbs: the current library button, the page heading and Back, Forward and Home already say where you are and move between pages.
- **Browsing while changing rooms:** joining, switching or leaving keeps the signed-in viewer’s Media page, scroll position, filters, search and browsing history. Room progress, Continue in this room and room actions update in place. A guest’s catalog is available for the lifetime of their room grant.
- **Show and season line:** an episode's details page names its show and season above its title ("Show · Season 1"), and a season's page names its show, each a link there. A show or season already passed on the way returns as it was left; otherwise it opens fresh, as when the episode was opened from the queue. At the end of an episode's line, previous and next episode buttons (the header's navigation button style, labelled "E5", or "S2 · E1" across a season boundary, with the full title as their name) open the episodes either side in the show, Specials left out; the first and last episodes show only the one that exists, and Back returns to the episode before.
- **Media tools:** search on its own row, then Sort, direction, Filters and "Set as auto-queue" (it acts on the list being browsed), with the view switch at the end. While browsing down the catalog these rows slide up behind the header and scrolling up a little brings them back; they stay while search is focused or Filters is open, and snap instead of sliding with reduced motion.
- **Watched progress:** cards and details artwork show a primary-accent progress bar along the bottom of the poster when progress is actionable (between 10 seconds and 92%), preferring the room's history over personal Plex progress. In details, Play now (primary), Resume at MM:SS, Add to queue and Suggest (quiet, no outline) share one row; a show or season's Add show/season to queue and Set as auto-queue are quiet buttons too, the latter keeping its secondary-accent icon (wrapping only when it is too narrow), with no note about replacing the current video. Editions and versions appear separately labelled, with an Other editions section in details.
- **Details backdrop:** when the media server has background art (Plex `art`, or the show's for an episode; Jellyfin Backdrop), it spans the top of a details page, faded out at the bottom and dimmed under the text, with the poster, title and actions starting partway down it. Without art the page keeps its plain layout; local libraries never have one.
- **Title logos:** a movie or show whose media server has a title logo (Plex clearLogo, Jellyfin Logo) crossfades it in over the text title once it loads, in the space reserved for it so nothing moves, with the title as its text alternative; the text shows until then and when the logo fails. A details page's logo and backdrop load ahead of other pictures, starting on click, or when a mouse pointer or keyboard focus rests on the title for a moment. One already fetched shows at once, with no text first and no fade; only one that arrives while the page is open fades in. Episodes and seasons keep their text title. Logos carry a soft shadow, plus a thin dark edge in the light theme so white logos stay legible.
- **Media Home rows:** above the library cards (then headed "Libraries"), Continue in this room (what the room started and left unfinished, newest first, each item only if this viewer may watch it), Continue watching and Recently added, each up to 20 tiles in one row that scrolls sideways at every width. Scrollbars are hidden; arrow buttons in the queue's style and fades at the edges indicate more content, with swipe, Shift-scroll and keyboard scrolling also available. Arrows disappear at their respective ends and both disappear when everything fits; reduced motion disables smooth scrolling. Account and data refreshes preserve unchanged tiles, focus and the visible title. Continue watching is each viewer's own: their Plex On Deck through their own Plex sign-in, as wide pictures with the progress bar and "Show · S2 · E4" or "1h 12m left"; a viewer without their own Plex sign-in (the shared fallback, or a Jellyfin-only install) sees no such row rather than someone else's progress. Recently added mixes every server's newest titles (Plex and Jellyfin; local libraries record no added date yet), newest first, as posters. Tiles keep their usual actions and open from their own server with their library current. A row with nothing in it is left out.
- **Library cards:** Libraries home has one card per library (owner-approved 2026-11-16): its icon on a small tinted square at the top left, and its name anchored to the bottom with the server under it, as that server's mark and own name (the Plex logo and "VIGRID"; the Jellyfin logo and its server name; "Local folders" for a local library). A library with collections has a Collections button in the card's top-right corner, which keeps only its icon on a narrow card; there are no separate collections cards. The synchronization test video is not on Libraries home: in Admin mode it appears as one more card, "Sync test video", marked "Admin mode".
- **Local libraries:** each configured local library is one more card on Libraries home, after the Plex libraries, using the existing home card with the `folder` icon (on its library button too), so it stands apart from movie libraries. It opens one title-sorted list of every video in its folders, or, for a library with `type: shows`, of its shows, which open to seasons and episodes like a Plex show. With `parse_names` (the default) a release name shows as the film's title, and its year and edition fill the details line as they do for Plex films; otherwise the file name is the title and the subfolder the subtitle line. It has no Collections button, genres or auto-queue source; its Filters panel offers release year only. Its pictures are the picture files beside a video when there are any, otherwise a frame from the video; a frame whose shape differs from the tile (a wide frame on a poster tile) sits whole and centred on a blurred, darkened copy of itself rather than being cropped (owner-approved 2026-11-16).
- **Jellyfin libraries:** each movie or show library of the configured Jellyfin user is one more card on Libraries home, after the Plex libraries, using the existing home card. Shows, seasons, posters, genre and year filters, sorting and auto-queue sources behave as they do for Plex; there is no Collections card.
- **Ending interstitial:** when a video ends, the occurrence completes to history and unloads, and the ending screen takes the stage with dimmed artwork, a center play button (with a countdown ring during autoplay), a short summary, Watch again and Browse media. The plain empty stage appears only with no current video, history or upcoming item. Play there selects the queued successor; restart stays a separate action.
- **Media suggestions (library):** in cards and posters views everyone who can suggest gets a top-left `bulb` button, alongside top-right Add to queue for people who can add directly. A suggested video's bulb stays lit without hovering and, once more than one person agrees, widens from a circle into a pill showing the count; an unavailable title offers neither button (its bulb still shows if it was suggested), and disabled buttons never take the hover highlight; clicking it suggests, agrees or stops agreeing, and the last person to stop removes the suggestion. There is no "Suggested" badge.
