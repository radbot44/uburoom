# uburoom design guide

Keep the established layout and behavior. The main site enters `/watch`; the standalone remote-only homepage is retired. The web-owned remote renderer is `web/remote-ui.js` (styles, SVGs, controls/badges), with the watch shell in `web/watch*.css`. uburoom-remote owns its own renderer and popup; do not import another checkout's UI files. Inspect affected renders before UI changes and use safe-DOM components.

## Visual language

Use Inter/system-ui/-apple-system/Segoe UI/sans-serif with existing fallbacks. Dark tokens: background #101217, card #1B1E26, elevated #292E38, border #393F4D, text #F8F7F4, muted #AAB0BC. Light tokens: background #F8F6F2, card #FFFEFC, elevated #F0ECE6, border #DDD7CF, text #242329, muted #706D77. Fixed brand references remain orange #FF9954 and pink #FF7197; semantic primary/secondary swap between them. Dark/orange is the explicit default, independent of system or browser appearance. Keep semantic green #158761 for enabled remote and semantic red for destructive/error states. Video stays black with dark chrome and light overlays; sibling menus/dialogs use the selected page palette. Accent-filled controls use dark text in either theme; light surfaces use a contrast-adjusted accent ink for text/icons.

Two compact switches immediately precede the username: Light/Dark and Orange/Pink, using the Room options pill/thumb styling at a narrower width. The theme thumb has a sun/moon icon, while the accent thumb has no icon. Both switches use accessible names rather than visible labels. The accent track stays neutral while its thumb shows the selected brand color. Persist appearance locally and apply it before rendering on watch, sign-in and handoff pages. Wordmark, remote logo and SVG favicon reuse the canonical artwork with theme-appropriate neutral ink and swapped primary/secondary colors; preserve the fixed-color source assets.

Accent changes interpolate primary/secondary colors and crossfade logos over 100 ms. Twenty accent clicks within five seconds reveal Sunrise Mode with a color burst, 100 ms fades and 50 ms holds. Continued clicks less than 250 ms apart keep it active; releasing leaves it running, and a click after a pause of at least 250 ms stops it and saves orange. The corresponding theme gesture produces a gray dud only. Keep effects local, transient and non-interactive, and suppress particle/button/logo motion for reduced-motion preferences.

Reuse 24×24 shared SVG paths, currentColor strokes, rounded ends/joins and approximately 1.9px width. Preserve rounded surfaces, subtle borders, spacing, focus and accessible names. Do not substitute emoji/icon libraries.

## Approved branding

The primary wordmark is `assets/branding/uburoom-wordmark-brand.svg` (944.16 × 293.5061): orange `ubu`, off-white `room`, pink underline. Runtime headers use its web-owned copy under `web/assets/` at its natural aspect ratio. `uburoom-wordmark-white.svg` is available for monochrome dark contexts.

The primary standalone oomark is `assets/branding/uburoom-oomark-brand.svg` (298.99 × 249.1061): off-white eyes and a pink mouth. `uburoom-oomark-white.svg` is its monochrome variant. The extension uses a square framed copy and PNG exports at 16, 32, 48, 64, 96, 128, 256 and 512 pixels; the favicon ICO includes 16/32/48 sizes.

Use the full-color wordmark for site headers and the oomark for favicons and toolbar icons. Do not stretch the wordmark into a square icon.

Raster/source exports in `assets/branding` include the 1848 px wide transparent wordmark PNG, 512 px transparent square icon, and 1024 px background square wordmark/oomark PNGs with matching SVGs. The prior blue/green assets currently reside in `assets/branding/old/`; M1 release cleanup will replace the old wordmark dependency in demo-media generation and remove that archive from the active tree (Git history retains it).

Use the canonical uburoom artwork. The initial theme script includes the SVG sources; appearance changes recolor cached local data URLs for header/remote logos and the favicon without network requests. Preserve the established typography and component layout rules above.

## Components

- Playback queue defaults to horizontal cards: chronological history on the left, the current video centered initially and after media changes, and upcoming entries on the right. Allow native scrolling, previous/next browsing arrows and explicit recentering; ordinary snapshots preserve browsing position and focused controls. Remember Cards/List locally. List puts current playback above history/upcoming columns, stacking upcoming before history on narrow panels. Keep the queue below the room bar and full width in theater, above Room options/Library. Reuse authenticated library artwork and existing icons; preserve replay, resume, queue editing, autoplay, generation settings and confirmed clearing through the shared command path.
- Queued items show Play now/Skip to directly, with Move earlier/later at the top right (left/right in Cards, up/down in List). Follow a moved card with smooth scrolling and retain its active control. Vertical wheel input retains native page scrolling; cards keep their scrollbar, arrows and native horizontal gestures. Match history/upcoming row heights and muted uppercase header typography; upcoming labels read `1 · UP NEXT in 43:32`, estimating from unfinished preceding playback. Use the queue-add icon for history requeueing, omit the Current video footer caption, and publish current/history/upcoming updates together when their revisions agree. Explicit replay consumes its selected room-history row with a fresh playback occurrence. Current Skip follows Play/Pause; history Go back to precedes Resume and restores newer history/current playback before the existing pending queue.
- Section headings are Queue, Room and Media. Room uses the web-owned monochrome oomark derived from canonical geometry; Media uses the existing drawer symbol. The fullscreen drawer button is Menu. Mobile sections use equal-width Room/Queue/Media tabs, one visible panel, roving keyboard focus and retained selection across Menu entry/exit; desktop sections retain their layout. Apply one shared panel margin rather than nested Room margins, and preserve page width between short and long tabs. The queue tab is unavailable without a durable room; Media remains browsable outside a room.
- Sticky Media headers use opaque rectangular backing so catalog content cannot show through their corners; the surrounding panel keeps its rounded outline. Back mobile tab corners/gaps with an opaque surface and place the sticky Media header below the measured tab bar. In the mobile fullscreen Menu, pin its toolbar below the measured Media header as well.

- Compact/normal remotes use one renderer. Enable is master, Playback/Picture are independent, Queue disabled, On join a remembered preference. Consent itself is never restored.
- Transport retains central double-height Play/Pause, ±15 seconds, icon-only actual-boundary Start/End, mute/volume. Slider drafts stay stable; web commands are throttled and unsent values dropped on disconnect/target change.
- Picture retains separate Zoom/Width/Height rows: minus above reset at left, editable value/label in the middle, larger plus at right, beside the pad. Resets are independent; Reset all is quiet gray. Keep hold/Ctrl, profiles and phone layouts.
- Applied-command badges use a 112px shared symbol, useful applied value and literal sender name; each command restarts the 2.5-second lifetime. Avoid verbose status.
- Watch places the library beside the video on wide screens, with the room bar below the video and above Room options. Narrow screens stack the library below. Personal quality/audio are separate from shared playback/picture. The centered Play/Pause button appears on hover or keyboard focus; a plain video-surface click does not toggle play.
- Normal content expands proportionally from a 1,750px cap at 1080p to 2,100px at 4K, with poster columns adapting to the available library width. Theater centers the landscape player above a room bar on the normal page background; cap player height so portrait screens cannot make it taller than wide. At the page top, dim all content below the video, revealing it on hover/focus below the player or page scroll. Put Room options and Library in approximately 25%/75% columns, keeping Room options sticky during library page scrolling and stacking on narrow screens. Keep the logo/header on the normal background.
- Mobile has no theater option and uses an edge-to-edge player with square corners. Desktop corners are subtly rounded; theater and fullscreen are square. The mobile transport has two rows: timestamps/progress, then Play, Beginning, End, CC, Settings, mute/visible volume slider and Fullscreen. Keep mute adjacent to its slider. Side double-taps seek 15 seconds; each extra tap adds 15 seconds in that direction. Touch controls hide after inactivity, including after slider use, while blocked playback and active menus remain reachable.
- Player settings use a desktop drop-up ordered Quality, Audio track, Subtitle track, More settings, with choice menus opening left. Mobile opens the full dialog, including in fullscreen. The dialog groups playback/Sync correction, tracks and subtitle rendering/delay. CC is an outlined rounded rectangle when off and solid with cutout letters when on; it restores the previous/default available track and fades when no track is available. Quality badges on the cog show ORIG or HD for Original/1080p, with no badge below that. Native captions clear the actual control height and return down when touch controls hide; explicit cue positioning stays intact.
- Quality choices include the resolution suffix (1080p/720p). Selected menu choices use the existing orange text/background without an edge stripe. The main audio/subtitle summary shows the resolved track even for Automatic; the choice menu keeps Automatic checked and marks its resolved track as Used by Automatic. Format track summaries from language, codec and channel layout, with custom names in a separate muted caption row.
- Browser fullscreen uses actual fullscreen and provides a half-width drawer, nearly full width with an external close-button gutter on portrait phones. Exiting restores the prior normal/theater layout. Clicking Theater while fullscreen exits into theater. Use an orange Theater icon without an accent fill. Remember the browser normal/theater preference and apply it before parsing watch content; do not persist fullscreen or apply theater on mobile/Activity. Clicking outside the drawer closes it; keep its close button outside the upper-left edge, with a visible left gutter on portrait phones. Activity uses this viewport-filling layout with theater unavailable; PIP is video-only. Preserve private confirmation/revocation and room chooser behavior.
- Library scrolls independently only while beside the video in wide normal layouts, with its heading and toolbar pinned inside the panel and the top padding fully covered. Below-video libraries use page scrolling, including in theater and narrow layouts. Use the same card background for the library toolbar and elevated backgrounds for button groups. Omit the Library/Collections selector; collections remain reachable from Libraries home. Preserve poster/list views, explicit library/show/season/episode breadcrumbs, navigation/view selectors, paging and search/scroll restoration. Episodes use scene-only detail art; movie posters match grid sizing. Row details stay separate from enlarged Play controls. Artwork is authenticated. A quiet Back to top button returns to the player; accepted library Play selections do the same, closing the fullscreen/Activity drawer and moving keyboard focus to the player. Show Back to top only in theater, at the right of the sticky library navigation row; truncate breadcrumbs with ellipsis before the button.
- Account/privacy/handoff dialogs use existing inputs, quiet/primary buttons and shared symbols. Account settings use matching provider rows with usernames, official Discord/Plex icons and connection state; IDs belong only to the collapsed owner matching tool. A remove icon opens confirmation; disconnected providers show a larger Connect button in the same right-hand position. Protect the last sign-in method. Discord sign-in uses official blurple. Browser logout retains bottom placement/spacing and is hidden for Activity bearer identity. Initial checking and sign-in choices overlay the inactive watch layout; reveal choices only after an unauthenticated response and offer retry on errors.
- Outside a room, keep Room options visible, faded and inert, with the authenticated library fully browsable. Library Play opens the create/join dialog: choose public/private visibility before creation, or join an accessible active room's current playback. Cancel preserves the current catalog view. Creating from Play loads the selected title through the shared command engine.
- The username opens account settings; do not add a separate account cog. Refresh rooms belongs in the room bar immediately before New room.

Test affected normal/theater/phone surfaces using isolated fixtures. Actual player/Activity results stay separate. Private design transcripts and historical screenshots are not public documentation.
